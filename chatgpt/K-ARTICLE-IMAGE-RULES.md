# K-ARTICLE 대표이미지 품질·저장 규칙 v2.0 — FROZEN

기준일: 2026-08-14
상태: FROZEN / K-ARTICLE-RULES에 대한 필수 이미지 규칙

## 1. 이미지 제작 품질
1. 대표이미지는 반드시 고품질 생성형 이미지 모델(image generation)을 사용해 제작한다.
2. Python/PIL 도형 조합, 저해상도 합성, 단순 인포그래픽 방식으로 대표이미지를 새로 그리지 않는다.
3. 기본 형식은 사실적인 산업 현장 사진형 이미지로 한다. 기사 핵심 장면 하나만 표현한다.
4. 기사 제목, 통계, 차트, 표, 기업 로고, 설명 패널을 이미지에 넣지 않는다.
5. 반도체 기사에서는 실제 FAB·클린룸·장비·엔지니어의 구조와 복장이 자연스럽고 전문적으로 보여야 한다.
6. 인물의 손·얼굴·보호복, 장비 구조, 원근, 조명 등 시각적 오류를 저장 전에 확인한다.
7. 원본 이미지는 가능하면 16:9 고해상도로 생성하고, 게시용 JPG는 1200×675로 정규화한다.
8. 우측 하단에만 `생성형 AI 제작 이미지` 문구를 작고 선명하게 표시한다.
9. 이미지가 기사 주제를 직접 설명하지 못하거나 품질이 낮으면 GitHub에 저장하지 않고 재생성한다.

## 2. 실제 JPG 바이너리 저장 원칙
1. 최종 파일은 반드시 `YYMMDD.AutoGen.기사제목.jpg`라는 **실제 JPEG 바이너리 파일**로 `wskimgit/k-article/main`에 저장한다.
2. `.jpg.b64`, `.b64`, `.txt` 등의 우회 파일을 대표이미지로 저장해서는 안 된다.
3. Base64 문자열 자체, `placeholder`, data URI, 빈 파일, 임시 청크 파일을 최종 이미지로 간주하지 않는다.
4. Base64는 GitHub API로 JPEG 바이너리를 전달하기 위한 **전송 인코딩**으로만 사용할 수 있으며, 저장 경로의 확장자는 반드시 `.jpg`여야 한다.
5. 업로드 과정에서 임시 `.b64` 또는 청크 파일을 만들었다면 최종 JPG 저장 확인 후 즉시 제거한다.
6. TXT와 JPG의 stem은 확장자를 제외하고 완전히 동일해야 한다.

## 3. GitHub 저장 후 필수 검증
이미지를 로컬에서 생성한 것만으로는 저장 완료가 아니다. 반드시 GitHub 원격 저장소를 다시 조회해 다음을 확인한다.

1. 정확한 `.jpg` 경로가 `k-article/main`에 실제 존재하는가.
2. GitHub에서 해당 파일을 Base64로 다시 읽었을 때 JPEG가 정상적으로 반환되는가.
3. JPEG 시작 시그니처가 `FF D8`이며, 가능하면 종료 시그니처 `FF D9`와 정상 decode까지 확인하는가.
4. 게시용 크기가 1200×675인지 확인하는가.
5. 파일 크기가 0바이트 또는 비정상적으로 작은 placeholder 수준이 아닌가.
6. 새 저장 또는 교체 후 blob SHA가 확인되는가.
7. 같은 stem의 `.jpg.b64` 또는 기타 우회 파일이 남아 있지 않은가. 남아 있으면 삭제한다.
8. GitHub 재조회가 404이거나 실제 JPEG 검증에 실패하면 **이미지 저장 실패**로 판정하고 재시도한다.

## 4. 완료 판정 금지 조건
다음 중 하나라도 해당하면 `이미지 저장 완료`, `ERRC PASS`, `기사 생성 완료`라고 보고해서는 안 된다.

- 이미지가 작업공간에만 존재하고 GitHub에는 없는 경우
- GitHub에 `.jpg.b64`만 존재하는 경우
- 파일 내용이 `placeholder` 또는 Base64 텍스트인 경우
- `.jpg` 경로 조회가 404인 경우
- JPEG decode 또는 시그니처 검증에 실패한 경우
- TXT와 JPG stem이 다른 경우

TXT만 정상 저장된 경우에는 반드시 `기사 저장 성공 / 이미지 저장 실패`로 구분해서 보고한다.

## 5. 최종 저장 절차
`고품질 이미지 생성 → 육안 품질검사 → 1200×675 JPEG 정규화 → JPEG 바이너리 검증 → 실제 .jpg 경로로 GitHub 저장 → GitHub 원격 재조회 → SHA·시그니처·크기 확인 → 우회 .b64 파일 부재 확인 → 완료 보고`

이 규칙은 이후 모든 K-BIZPOST egTEC AutoGen 대표이미지에 필수 적용한다.
