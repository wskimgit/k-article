## 필수 실행 순서
`재사용 근거 확인 → 허용 자료만 선택 → 사실 검증 → 독자적 문장·구성·사업 및 투자 해석 → 일반 기사체 편집 → 게시 전 검증 → 저장·확인 → 종료`

1. 기사 v2.6 §6.1과 이미지 v2.8 §1.1에 따라 자료 선택 전에 재사용 근거를 확인한다. 권리자의 허락, 적용 가능한 공개 라이선스·공공 재사용 정책, 확인 가능한 퍼블릭 도메인 또는 자체 원자료 권리 기록 등 실제 근거가 필요하다.
2. 공식자료·공개 열람·무료 다운로드·출처 표시·AI 작성만으로 허용하지 않는다. '사실만 독자적으로 바꿔 쓴다'는 이유로 재사용 근거 없는 자료를 PASS시키지 않는다.
3. 침해 사실 확인·침해 우려·조건 위반은 EXCLUDE, 근거나 범위 미확인은 HOLD로 판정한다. 둘 다 선정·입력·기사 근거에서 제외한다. 제외 자료에서만 가져온 사실·수치·해석도 허용된 별도 원자료에서 검증하지 못하면 제거한다.
4. PASS 자료의 사실 메모에서 제목·리드·문장·문단 순서를 독자적으로 설계한다. 타사의 기사 구성·특징적 표현·투자 논리·추천·목표주가를 번역·축약·치환해 재포장하지 않는다.
5. 투자 해석이 필요하면 해당 FAB 기술 변화와 연결되는 사실·성립 조건을 근거로 새로 작성한다. 단순 시황·종목 추천으로 범위를 확대하거나 확인하지 않은 전문가 발언을 만들지 않는다.
6. 본문은 뉴스 리드와 자연스러운 문단을 갖춘 일반 기사체로 완성한다. 분석서형 소제목·번호·불릿·점수표·체크리스트·내부 심사 용어를 본문에 넣지 않는다.
7. `chatgpt/copyright-checks/YYMMDD.<식별자>.json`에 자료별 근거·조건 준수·사실 연결·독자 작성·기사체 점검·제외 조치를 기록한다. 기록 저장 없이 COMPLETE를 보고하지 않는다.
8. 허용 자료가 부족하면 HOLD한다. 기사만 PASS이고 이미지만 실패하면 해당 이미지를 제외하고 기사·검증표만 저장하여 PARTIAL로 종료할 수 있다.
9. 무참조 AI 생성과 기존 이미지 동일 SHA 재사용도 이용 근거·최종 저작권 점검을 면제하지 않는다. 검증을 실제 법적 무침해 보증으로 보고하지 않는다.
10. 고지 v1.1에 따라 기사 아래 AI 고지를 두고, 그 아래 실제 PASS 출처와 필요한 라이선스 표시를 정리한다. 검증 기록은 기사 본문과 분리한다.

## 유지되는 이미지 전송 규칙 — GITHUB-SAFE IMAGE PROFILE
1. GitHub 게시용 이미지는 고품질 원본과 분리된 경량 JPEG로 저장
2. 기본 1200×675 / RGB / 메타데이터 제거 / 4:2:0
3. JPEG Quality 약 35~40, 목표 파일 크기 **12 KB 이하**
4. 12 KB 초과 시 같은 이미지에 대해 압축 조정은 1회만 허용
5. 그래도 초과하면 960×540 fallback 1회
6. 품질값 반복 탐색 및 다중 `q*.jpg` 시험파일 생성 금지
7. GitHub 저장 전 SOI `FF D8` + EOI `FF D9` + 실제 decode + 해상도 확인
8. GitHub 저장 후 원격 바이트 길이 = 로컬 바이트 길이 확인
9. 원격에서도 SOI + EOI + 해상도를 확인해야 COMPLETE
10. SOI만 맞는 잘린 JPEG는 PASS 금지
11. 저장 실패를 이유로 이미지 재생성 금지
12. 성공 후 원격 확인 1회만 수행하고 즉시 종료

## HARD STOP
- 생성 최대 2회
- 안전 JPEG 변환은 기본 1회 + 압축 조정 1회 + 해상도 fallback 1회
- GitHub 저장 충돌 재시도 최대 1회
- 원격 완전성 검증 성공 즉시 종료
- 우회 저장 경로 탐색 금지
