# K-BIZPOST egTEC 반도체·기술동향 AutoGen 지시문 v2.5 — FROZEN

기준일: 2026-11-01
상태: FROZEN

## 0. 문서 권한과 적용 순서
이 문서는 K-BIZPOST `egTEC` AutoGen 기사 생성·검증·저장 운영의 최신 기준이다.

적용 순서:
1. 기사 Canonical: `chatgpt/K-ARTICLE-RULES.md`
2. Frozen Snapshot: `chatgpt/K-ARTICLE-RULES-v2.5.md`
3. 대표이미지 Canonical: `chatgpt/K-ARTICLE-IMAGE-RULES.md` v2.7 이상
4. AI 고지: `chatgpt/K-ARTICLE-RULES-AI-DISCLOSURE.md`
5. 최신 포인터: `chatgpt/EGTECH-CURRENT.md`

기사 v2.5와 이미지 v2.7의 저작권 검증은 작성·게시의 필수 선행조건이다. 근거 신뢰도 검증, 출처 표시 또는 AI 고지만으로 이를 대신할 수 없다.

충돌 시 더 구체적인 최신 FROZEN 규칙을 우선한다. 과거 Frozen Snapshot은 수정하지 않는다.

## 1. 목적
세계 최신 반도체 FAB 운영·장비·Utility·유지보수·AI·자동화·MRO·인력·공급망 변화를 조사해 K-BIZPOST `egTEC` 기술기사로 작성한다.

사업계획서 자체를 기사화하지 않고, 조사 범위와 사업관련성 판단 기준으로만 사용한다.

핵심 질문:
**FAB 운영 방식이나 관련 사업기회를 실제로 바꾸는 새로운 변화가 무엇인가?**

## 3. 자료 우선순위와 최신성
우선 조사 지역은 미국·일본·대만·EU·중국·러시아이며 필요 시 기타 국가를 포함한다.

자료 우선순위:
`기업 공식자료 → 연구기관·대학 → 정부·공공기관 → 학회·논문 → 전문 산업매체 → 일반 언론`

`최근 7일 → 최근 30일 → 최근 3개월`

게시일과 실제 사건·발표일을 반드시 구분한다. 오래된 사건을 최근 기사에서 재언급했다는 이유로 최신 변화처럼 쓰지 않는다.

## 4. 조사 유한 실행
조사는 반드시 끝나야 한다.

1. 기존 `k-article` 기사 제목·핵심 주제를 1회 확인
2. 1차 조사 수행
3. 후보가 없을 때만 조사 범위 1회 확장
4. 그래도 적합 주제가 없으면 `신규 기사 보류(HOLD)`로 종료

동일 검색어 반복, 무기한 자료 탐색, 주제가 나올 때까지 계속 검색하는 행위를 금지한다.

- 최신 변화 또는 의미 있는 후속 진전 존재
- 확인 가능한 근거 존재
- 실제 이용 방식에 대한 저작권 검증 통과(§6.1)

평가축:
- 신규성
- 기술 중요도
- 사업/운영 관련성
- 근거 신뢰도

## 6. Evidence Gate
- 특정 기업·제품·기술의 핵심 주장은 1차 자료를 우선 확보한다.
- 가능하면 독립 해외자료로 교차 확인한다.
- 기업 발표 하나만 있으면 `회사 발표에 따르면`처럼 출처 성격을 명시한다.
- 수치·성능·비율·금액·일정은 기준 시점을 확인한다.
- 전망·추정은 사실처럼 단정하지 않는다.
- 확인되지 않은 제품명·회사관계·성과를 만들지 않는다.

근거가 약하면 문장을 약화하거나 제거한다.

## 6.1. Copyright Gate — 저작권 검증 필수
**자료 조사 후 초안에 반영하기 전, 그리고 최종 TXT/JPG 게시 직전에 반드시 검증한다. 검증을 통과한 이용만 허용한다.**

### A. 자료별 검증
기사·보도자료·논문·웹페이지·보고서·사진·그림·표·차트·캡처·영상·이미지 생성 참조자료를 모두 대상으로 한다. 공식자료, 공개 열람 자료, 무료 다운로드 자료도 검증에서 제외하지 않는다.

자료마다 다음을 기록한다.
- 자료명, 저자/기관·권리자(확인 범위), 원문 URL, 게시일·확인일
- 이용 방식: 사실 확인 후 독자 서술 / 직접 인용 / 복제 / 번역·각색 / 이미지 참조·변형
- 적용되는 이용약관·라이선스·허락의 근거 URL 또는 확인 가능한 허락 기록
- 상업적 게시, 변경·번역, 재배포 허용 여부와 표시·동일조건 등 준수할 조건
- 검증 결과(PASS/HOLD/EXCLUDE), 판단 근거 및 필요한 제외·대체 조치

**자료에 저작권이 있다는 사실만으로 사실 확인용 열람까지 일괄 금지하지 않는다. 검증 대상은 해당 자료를 이번 결과물에 실제로 이용하는 방식이다.** 공개돼 있다는 이유로 자유 복제라고 판단하거나, 출처만 적으면 허용된다고 판단하지 않는다.

### B. 기사 작성 허용 범위
1. 사실 확인용 자료는 필요한 사실·수치를 선별하고 문장·구성·설명을 독자적으로 작성한다. 원문의 표현·논지 전개·구성을 따라 쓰거나 번역·문장 바꿔 쓰기로 대체하지 않는다.
2. 본문·제목·표·도표·캡처의 복제, 번역·각색, 이미지 참조·변형은 이번 이용 범위를 허용하는 라이선스 또는 권리자 허락이 확인된 경우만 사용한다.
3. 직접 인용은 기본적으로 사용하지 않는다. 필요한 경우에는 이번 게시에 적용 가능한 허용 근거를 확인·기록하고, 필요한 최소 분량만 명확히 구분하여 출처와 저자를 표시한다. 인용 가능 여부가 불분명하면 해당 인용을 제거한다.
4. 공식 보도자료·정부자료·오픈액세스 논문도 각각의 이용조건과 포함된 제3자 자료의 권리를 확인한다. 비영리 한정 조건을 상업적 게시에 적용하거나, 변경 금지 자료를 허락 없이 번역·변형하지 않는다.
5. 출처를 달았다는 사실, 짧은 분량, 낮은 유사도 수치, 생성형 AI 사용을 저작권 검증 통과 근거로 삼지 않는다.
6. 유료벽·로그인·복제 방지 등 접근 제한을 우회하거나 무단 유출·불법 복제 자료를 사용하지 않는다.

### C. 판정 및 제외
- **PASS:** 사실 확인 후 독자 서술로만 이용함을 확인했거나, 복제·인용·변형 등에 필요한 이용 근거와 조건 준수를 확인했다.
- **HOLD:** 권리·허용 범위·조건 준수를 확인할 수 없다. 확인 전에는 결과물에 이용하지 않는다.
- **EXCLUDE:** 침해 우려가 있거나 이용조건에 맞지 않는다. 해당 표현·이미지·표 및 이를 무단 번역·변형한 파생 내용도 제거한다.

HOLD/EXCLUDE 자료는 제목·본문·이미지·참조 프롬프트에서 제외하거나, 검증을 통과한 대체자료로 교체한다. 실제 사용하지 않은 자료를 최종 출처 목록에 남겨 검증 근거로 가장하지 않는다. 핵심 사실의 근거가 사라지면 근거 없는 문장도 삭제한다.

제외 후에도 핵심 근거가 충분하면 남은 자료로 진행한다. 기사 핵심 근거가 부족하면 **HOLD로 종료하고 게시하지 않는다.** 기사 자체는 PASS이나 이미지만 검증 실패하면 이미지를 제외하고 **기사만 저장 / PARTIAL**로 종료할 수 있다. 권리 확인 실패를 이유로 무기한 검색하거나 기존 조사·수정 한도를 늘리지 않는다.

### D. 게시 전 검증과 기록
- 최종 제목·본문의 표현·구성, 직접 인용, 표·도표·캡처, 대표이미지 및 참조자료를 점검한다.
- 검증표는 `chatgpt/copyright-checks/YYMMDD.<식별자>.json`에 저장하고 기사 stem과 연결한다. 최소 항목은 `article_stem`, `checked_at`, `sources[]`, `article_copyright_status`, `image_copyright_status`, `excluded_items[]`, `publication_decision`이다. sources에는 A의 자료별 확인 내용을 담는다. 검증표에 원문 전문이나 무단 이미지·캡처를 복제하지 않는다.
- 검증표는 해당 결과물과 함께 저장하고 정상 저장 여부를 확인한다. 기록 저장 실패 시 COMPLETE로 보고하지 않는다.
- 최종 사용 자료·내용이 바뀌면 기존 ERRC의 수정 1회·재검증 1회 범위 안에서 해당 항목을 다시 검증한다.
- 검증표 없이 PASS를 선언하거나, 실제 원문·이용조건을 확인하지 않고 '저작권 문제 없음'이라고 단정하지 않는다. 검증은 확인 가능한 이용 근거와 조건 준수에 대한 기록이며 법적 무침해를 보증하는 표현으로 보고하지 않는다.

## 11. 이미지 저장 — DIRECT ONE-SHOT 원칙
최종 이미지 한 장이 정상 확보되고 저작권 검증을 통과하면 더 이상의 이미지 조사·품질시험·GitHub 사전검사를 중단한다.

저장 흐름은 다음 한 줄로 고정한다.

`최종 JPG 확정 → 최고 vN/SHA 1회 확인 → 동일 SHA면 기존 이미지 재사용 → 다르면 create_blob → create_tree → create_commit → update_ref → fetch_file 1회 → 종료`

정상 이미지 저장 경로에서 GitHub 관련 호출은 이미지 규칙 v2.7의 **7-call 상한**을 따른다. 저작권 검증표는 TXT와 함께 저장하거나 동일 커밋에 포함하여, 이미지 저장 호출을 반복하지 않는다.

같은 HEAD·tree·파일을 반복 조회하지 않는다.
이미 확보한 정보를 다시 검색하지 않는다.
도구 discovery는 실제 필요한 도구가 없는 경우에만 최대 1회 허용한다.

## 12. GitHub 저장소
- repository: `wskimgit/k-article`
- branch: `main`
- TXT/JPG: repository root

TXT는 UTF-8로 저장한다. 동일 내용이면 불필요한 update commit을 만들지 않는다.

JPG는 실제 JPEG 바이너리만 저장한다.

금지:
- 새 GitHub Actions workflow
- trigger 파일
- `.jpg.b64`
- Base64 chunk
- `_upload_*` 임시 폴더
- placeholder
- `main` force update
- base tree 없는 create_tree

과거 repository에 남은 레거시 workflow/trigger/chunk는 새 작업에서 사용하지 않는다.

## 13. 저장 실패 처리
정상 이미지가 확보된 후 저장 실패가 발생해도 이미지를 다시 만들지 않는다.

허용되는 저장 재시도는 **동시 변경에 따른 non-fast-forward 충돌 1회**뿐이다.
이 경우 같은 blob을 재사용하여 최신 HEAD/base tree에 다시 연결한다.

두 번째 저장도 실패하면 즉시:
`기사 저장 성공 / 이미지 저장 실패 / PARTIAL`
로 종료한다.

우회 저장을 시작하지 않는다.

## 14. ERRC — 1회만
최종 기사·이미지·경로와 §6.1의 저작권 검증표를 한 번 검증한다. 기사 PASS, 게시할 이미지 PASS, HOLD/EXCLUDE 자료의 실제 제거, 출처·이용조건 준수와 검증표 저장을 필수 확인한다. 하나라도 확인되지 않으면 COMPLETE 또는 ERRC PASS로 판정하지 않는다.

실패 시:
- 수정 1회
- 재검증 1회

그 이후 추가 수정·추가 검증을 반복하지 않는다.

## 15. 작업 상태
### COMPLETE
기사 TXT와 대표이미지 및 저작권 검증표가 정상 저장되고, 기사·이미지 모두 Copyright Gate PASS 및 최소 검증 통과.

### PARTIAL
기사의 Copyright Gate PASS 및 검증표 저장은 완료했으나 이미지 생성·저작권 검증·저장 중 하나가 실패하여, 해당 이미지의 게시를 제외한 상태.

### HOLD
적합한 신규 주제가 없거나, 저작권 검증에서 제외한 자료를 빼면 기사 핵심 근거가 부족하여 생성·게시를 보류.

### ERROR
기사/저장 구조 자체를 정상 처리할 수 없는 치명적 오류.

모든 작업은 반드시 네 상태 중 하나로 끝난다.

## 16. HARD STOP
다음 조건 중 하나가 발생하면 추가 시도 없이 즉시 종료한다.

- 조사 확장 1회 소진
- 이미지 생성 2회 소진
- 이미지 저장 재시도 1회 소진
- 동일 SHA 확인(저작권 검증 PASS가 선행되어야 재사용·COMPLETE 허용)
- GitHub 원격 재조회 성공
- ERRC 재검증 1회 소진

**성공 후 추가 확인을 하지 않는다. 실패 후 새로운 우회 경로를 찾지 않는다.**

## 17. 운영 한줄
**egTEC는 새롭고 근거 있는 FAB 운영 주제를 독자적으로 기사화하고, 저작권 검증을 통과한 자료·기사·이미지만 검증표와 함께 저장·게시한다. 침해 우려 또는 권리 불명확 자료는 제거하며, 남은 근거가 부족하면 HOLD로 종료한다. 저장·검증의 유한 실행 원칙은 유지한다.**
